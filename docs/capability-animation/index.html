Transcript and technical sources

00:00 · The request. A client agent sends a program to the compiler through the gateway. Ordinary computation runs freely. Protected functions need permission.

00:10 · The grant. The connection owner grants a user specific language functions, such as saving to the item bank. The provider credential stays inside the broker.

00:20 · Admission. The gateway preflights every compiler stage. Policy checks the entire chain. One denied function blocks the run before any stage executes.

00:30 · The capability. Policy issues the compiler a capability: single use, valid for sixty seconds at most, bound to the function and exact arguments.

00:40 · Live checks. Broker verifies the capability and checks live permission before each effect. Active grants allow the provider call. Revoked permission blocks the next effect.

00:50 · Safe retries. A durable receipt records the outcome. Retrying the same operation returns its receipt without repeating the write. The agent gets results, never credentials.

Based on the repository's security specification, implementation record (W4 activated October 13, 2026), registry v7, and compiler's protected client.

Live checks can block the next effect; they cannot undo dispatched operations. Receipt replay prevents the same operation from being executed again by Broker; it does not promise provider transactionality or exactly-once provider effects. Outcomes include success, failed, partial, and uncertain.
