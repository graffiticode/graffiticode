What a compromised compiler can reach without ISOLATE-01

Today's production: no egress controls on any compiler

Compilers run as public Cloud Run services, each with its own lNNNN-run account and no VPC, proxy or allowlist. Policy, Broker and the registry still gate every brokered operation, so a well-behaved compiler can only act on Learnosity through Broker. ISOLATE-01 is about a compromised one: a malicious dependency or a bad build. The red flows below succeed today.

The vulnerabilities, and what closes each

  1. 1
    Anything a compiler sees can leavePrograms, item content, a pipeline's earlier-stage data and a user's form state go to any host. Nothing records where.With ISOLATE-01: every compiler but L0185 reaches only its reviewed hosts, and the proxy logs every request, refused ones included.
  2. 2
    L0158 holds the shared Learnosity credentialIts deploy mounts learnosity-secret, so a compromised L0158 can call Learnosity directly: no Policy, no Broker, no receipt, no audit.Closed 2026-10-15, without an exception: L0158 renders through L0176, which signs only through Broker, and holds no credential. learnosity-secret was deleted on 2026-10-18.
  3. 3
    A credential found in a program works anywhereA key pasted into a program or its data can be used against the provider from the compiler, outside every check.With ISOLATE-01: provider hosts, IP literals and fronted requests are refused for every class.
  4. 4
    A compiler's identity can be shipped outAn ID token for Policy or Broker, sent elsewhere, lets someone call as that compiler until it expires. Policy and Broker still demand a user's invocation or execution token, so this widens the surface rather than opening the provider.With ISOLATE-01: the token can't leave; only the metadata server is reached directly.
  5. 5
    L0185's fetches rest on its own codeNothing outside L0185 stops a program's URL from naming the metadata address, a private address, a Google API or any public host.With ISOLATE-01 (D2): still open to public hosts, but run.app, googleapis.com, internal and Learnosity names, IP literals and every internal address are refused.

What still holds without it

  • Broker is the only place the per-user connection credentials live, sealed; no compiler can read them.
  • Every brokered operation needs a Policy execution token bound to one operation, its arguments' digest and a single-use jti, minted for a user's invocation and checked live.
  • Broker accepts a token only from that language's own compiler identity, and claims a receipt before it calls the provider.
  • Compiler accounts hold no project roles, so a metadata token can't alter deployments or IAM.

These stop a compiler from misusing Broker. They can't stop it from going around Broker, which is what an egress control is for.
